## 3. Reworks majeurs proposés (avec validation state of the art)

### A. Type canonique + validation unique (Zod) dans `shared/` — **le plus rentable**

- **Constats** : 3 types `CharacterSheet` divergents (D1), un validateur manuel qui a déjà mordu (piège n°4 du handoff : `pvTemp` requis dans la feuille), aucune validation des payloads WS (A3 : le DO revalide tout à la main avec `Number.isFinite`/`Math.trunc` dans 15 handlers).
- **Proposition** : un schéma Zod `characterSheetSchema` dans `shared/src/sheet.ts` (ou en remplacement de `validation.ts`), qui :
  - infère le type canonique `CharacterSheet` (fini les 3 copies, y compris `vitesse: string`),
  - valide la feuille (remplace `validateCharacterSheet`),
  - valide les messages WS (remplace le switch manuel du DO par `schema.parse(msg)`),
  - sert de schéma Hono aux routes REST (avec `zValidator`, cf. B).
- **Justification** : c'est le pattern officiel du stack Cloudflare (Hono recommande Zod + RPC, la doc `hono.dev/docs/guides/best-practices` chaîne `app.route(...)` + `hc<AppType>`), et le contrat « le serveur revalide TOUT » du design §5 est aujourd'hui à moitié tenu. Zod ≈ 60 Ko minifié — acceptable pour un Worker unique et déjà payé par la suppression de `api.ts` manuel.
- **Effort** : ~2 jours (schéma + migration des handlers WS + tests conservés). **Élimine D1, D7, et la moitié de A3.**

### B. Client API typé Hono `hc<AppType>` (A6 de l'audit précédent, toujours ouvert)

- **Constats** : `web/src/lib/api.ts` (338 l.) réécrit à la main les types de chaque réponse REST — exactement ce que `hc` fournit. Les types `CampaignSummary`, `CharacterDetail`, `NpcTemplate`… sont les mêmes que ceux des routes.
- **Proposition** : exporter `AppType` depuis `api/src/index.ts`, consommer via `hc<AppType>` dans `web/src/lib/api.ts` (l'API de fetch reste, mais typée). Le monorepo pnpm y est prêt (`strict: true` partout — prérequis documenté Hono).
- **Effort** : ~1 jour, débloque aussi la cohérence quand on ajoutera la route « montée de niveau » (9c).
- ⚠️ Le WS (protocole) n'est PAS couvert par `hc` — garder `shared/protocol.ts` (déjà le bon modèle).

### C. Middleware d'autorisation paramétré (SOLID : open/closed)

- Un seul `requireMembership(param = "campaignId")` + `requireRole("mj")` qui posent `c.set("membership")` ; chaque route arrête de refaire son select. Idem pour les routes qui résolvent un objet par `:id` (char/map/template) : un helper `getCharOr404(c)` qui charge + vérifie la campagne **dans le même WHERE** (déjà fait dans le DO, à étendre au REST).
- **Effort** : demi-journée. Élimine D3 (~200 lignes dupliquées).

### D. Split des deux monolithes UI

- `CharacterSheet.svelte` (1905 l.) et `table/+page.svelte` (1625 l.) concentrent script + template + CSS. La feuille a des frontières naturelles : colonne Caracs, colonne Combat (CA/init/vitesse/PV/morts), Attaques/Armures/Sorts, Traits/Équipement.
- **Proposition** : extraire en sous-composants à props explicites (les `$state` de la feuille descendent), le CSS suit. Le gain réel est la navigation : chaque bloc devient testable/lisible.
- **Effort** : ~2-3 jours, à faire **après** A (sinon on split un fichier qu'on va réécrire). Pas bloquant pour la suite fonctionnelle.

### E. Store WS en runes Svelte 5 (modernisation, petit)

- `ws.ts` est un store pré-runes (Set de listeners + `notify()`). Svelte 5 offre les stores runes (`$state` partagé) — plus idiomatique, moins de code, réactivité native. Alternative conservatrice : garder l'objet mais l'exposer en `$state` via `createSharedState`.
- **Effort** : demi-journée. Gain modéré (le code actuel marche), à faire si on touche déjà `ws.ts` pour B8.

### F. Tests d'intégration du DO (la plus grosse lacune de confiance)

- **Constats** : toute la logique WS (combat, initiative, brouillard, PNJ) n'a **aucun test** — les 221 tests couvrent le pur (shared) et les parsers, jamais le DO ni le protocole bout-en-bout. Le handoff 05/09 l'admet : la « vraie session 2 navigateurs » n'a jamais eu lieu.
- **Proposition** : `@cloudflare/vitest-pool-workers` (pattern documenté Cloudflare) pour tester `GameTableDO` : connexion simulée, `token.move`, `mode.set` → combat, `initiative.roll`, filtrage PNJ/brouillard. C'est le filet qui permettra de faire A/B/C/D sans peur.
- **Effort** : ~2 jours. Priorité **haute** avant le prochain gros chantier fonctionnel (9c level-up).
