## 2. Pièges rencontrés — à ne plus re-faire

### Données temps réel / clés Svelte
1. **`each_key_duplicate` = page entièrement morte** (3 sources distintas, toutes vécues) :
   - ids de journal « live » inventés côté applicatif → **toujours écrire en D1 d'abord, diffuser l'id réel** (`.returning()`) ;
   - présence avec le même `userId` deux fois (socket hibernant après rechargement / double onglet) → dédup **serveur ET client** ;
   - règle défensive : sur toute liste temps réel, clé **composée avec l'index** (`id + ':' + i`) — aucune donnée serveur ne doit pouvoir crasher un rendu.
2. **`effect_update_depth_exceeded`** : un `$effect` qui réassigne un prop avec un nouvel objet (`char = {...char}`) à chaque notification WS se redéclenche lui-même. Sauvegarder **uniquement sur vrai changement de valeur** (comparer avant d'écrire).
3. Ne jamais nommer une variable `state` à côté du rune `$state` ; les `bind:value` génériques (`T extends string|number`) sur une prop `number` ne passent pas le typecheck → API explicite `value` + `onchange`.

### Modèle de données / validation
4. **Valider ce qui est réellement envoyé** : la validation exigeait `pvTemp` dans la feuille (c'est une colonne du personnage, pas un champ de `sheet`) → tous les PUT échouaient. Test = une vraie fiche complète.
5. **Changer de sémantique = migrer les données** : passer de « caracs = valeur finale » à « caracs = base + racial dérivé » oblige à corriger seeds/fiches existantes (Kaelith `dex:17→15` en local ET remote via SQL). Sinon double compte.
6. **Un seul chemin de calcul** : tous les consommateurs de caracs passent par `effectiveCarac`/`getMod`. Toute nouvelle valeur dérivée (PV, DD, initiative) doit lire par là, jamais `sheet.caracs[x]` direct.
7. **Interdiction produit apprise ce jour** : pas de bouton « appliquer » pour un calcul — le dérivé doit suivre instantanément (CON↑ ⇒ pvMax↑, badge racial auto). L'échappatoire manuelle existe (`pvAuto=false`) mais n'est jamais *requise*.

### Chaîne d'outils
8. **pnpm 10** : `pnpm deploy` est une commande **native pnpm** → toujours `pnpm run deploy`. `pnpm.onlyBuiltDependencies` dans package.json est ignoré → `pnpm-workspace.yaml`.
9. **wrangler** : changer `database_id` orpheline le D1 simulé local (empreinte du fichier `.wrangler/state/.../d1`) → restaurer via `VACUUM INTO` vers le nouveau hash. `filter-repo` **supprime le remote origin** (re-add + force push). Migrations = `pnpm db:migrate[:remote]` ; `--apply` de l'ingest est additif/upsert uniquement (jamais de delete).
10. **sharp/libvips précompilé ne lit pas BMP** → le générateur de portraits est un **outil local** (repli `sips`), les webp sont **commis**, la CI ne fait que les servir.
11. **Prédateurs de sed/python** : oxfmt reformate tout → relire le fichier avant chaque patch ; un script multi-`rep` qui casse à mi-chemin **n'a rien écrit** (ou pire, un fichier sur trois) → après tout patch scripté, `grep` de vérification obligatoire (2 incidents : validation portrait, script CharacterSheet).

### UI/UX
12. `min="1"` sur une **prop de composant** passe une string (TS) → `min={1}` ; les `<datalist>` natifs sont jugés « pas dingues » par l'utilisateur → préférer les popups grille de cartes (`ChoicePicker`) avec saisie libre en zone « personnalisé » (homebrew toujours possible).
13. Les overlays `position:absolute` dans un parent non `relative` se collent en haut à gauche → l'overlay de dé est `fixed` plein viewport ; durée de jet = **3,2 s** (réglable via prop).
