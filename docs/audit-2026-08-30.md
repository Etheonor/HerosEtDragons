## 3. Bugs fonctionnels confirmés (batch de hot-fixs, petits diffs)

1. **✅ CORRIGÉ (30/08) — Journal : les 50 PREMIÈRES entrées au lieu des 50 DERNIÈRES.**
   `api/src/do/game-table.ts` → `getJournalTail()` (~:1167-1175) : `orderBy(schema.journal.id).limit(50)`
   sans `DESC`. À la reconnexion, le snapshot renvoie le début de la campagne.
   Fix : `orderBy(desc(id))` puis `.reverse()`. (Violé R13.3/R7.)
2. **✅ CORRIGÉ (30/08) — Flux d'invitation mort (circular deadlock)** — R1.1/design §8.
   - `api/src/auth.ts` : `session.create.before` refuse tout login si le discordId n'est pas dans
     `allowed_users` ; le seul chemin d'ajout lit le header `X-Invitation-Token` dans
     `user.create.after` — mais le callback OAuth est un redirect navigateur : **ce header n'arrive
     jamais**. Et `POST /api/campaigns/join/:token` exige `requireAuth`… donc une session déjà créée.
   - Conséquence : impossible d'onboarder un nouvel ami sans insérer manuellement son discordId dans D1.
   - Fix recommandé : route publique `/join/:token` (avant login) qui pose un cookie `hd-invite`
     (SameSite=Lax, courte durée) ; `auth.ts` lit ce cookie dans les headers de la requête de callback
     et consomme l'invitation (atomique, voir §5.4).
3. **✅ CORRIGÉ (30/08) — Jets de la feuille non câblés** (R10.2) : `web/src/lib/components/CharacterSheet.svelte`
   n'émet aucun `dice.roll` (grep confirmé : seules interactions = REST pv/inspiration).
   Une bonne partie du pitch (« tout est jetable ») est là.
4. **✅ CORRIGÉ (30/08) — Autorité dupliquée REST vs WS** : `PATCH /api/characters/:id/pv` (characters.ts:190) ne notifie
   pas le DO → les autres clients ne voient pas le changement avant re-snapshot. Le RPC
   `stub.notifyCharacterUpdated` promis par design §2/§5 **n'existe pas**, le message `char.updated`
   n'est jamais émis par le serveur et jamais traité par le client `ws.ts`.
   Fix de fond : toutes les mutations de séance passent par le WS ; REST limité à la feuille ;
   API feuille → RPC DO → broadcast `char.updated` → refetch client.
5. **✅ CORRIGÉ (30/08) — RNG biaisé** : `makeRng()` (game-table.ts:299-307) fait `getUint32() % max` (modulo bias) alors
   que design §5 promet du rejection sampling. Équité des dés = confiance des joueurs. Fix ~4 lignes
   (rejet sur le multiple maximal de `max` ≤ 2³²).
6. **✅ CORRIGÉ (30/08) — `active` multi-PJ non borné** (R1.4) : plusieurs PJ `active=true` possibles pour un même user →
   l'attach WS choisit un personnage aléatoirement (`index.ts:46-56`, `.limit(1)` sans ordre).
   Fix : endpoint `set-active` + contrainte + sélecteur dans la barre de session.

## 5. Sécurité

1. **Fuite inter-campagnes via le WS (le plus sérieux)** : les handlers requêtent `characters` **par id
   seul**, sans `campaignId = this.campaignId` :
   - `handleCharHp` (~~:355), `handleCharCondition` (~~:398), `handleNpcRemove` (~~:562),
     `handleInitiativeRoll` lookup char (~~:878).
     Un membre connecté à la campagne A peut muter/supprimer les personnages de la campagne B (s'il
     devine/connaît l'UUID — ex-ami, journal partagé, etc.).
     **Fix : ajouter `.and(eq(schema.characters.campaignId, this.campaignId))` partout.**
2. **`PUT /api/characters/:id/sheet` sans aucune validation** (characters.ts:322-356) : JSON
   arbitraire accepté (carac 999, `pvMax` gonflé, taille illimitée), `sheetsLocked` jamais vérifié
   (R10.10), aucune détection dérivés-stocks (guardrail design §5). → schéma zod + bornes
   (carac 3–30, niveau 1–20, longueurs) + verrou MJ + limite de taille.
3. **PV des PNJ diffusés aux joueurs** : snapshot + deltas `characters` portent le `pv` des PNJ même
   avec `pnjPvVisible=false` ; seul l'UI filtre (`ws.ts:174`, table page). Contredit R4.2 + l'esprit
   du guardrail « visibilité serveur ». → filtrer dans le DO selon rôle + settings.
4. **Compteur d'invitations non atomique** : `usesLeft: inv.usesLeft - 1` lu puis écrit
   (`auth.ts:106-109`, `campaigns.ts:266-269`) → deux jointures simultanées = double usage.
   → `set({ usesLeft: sql\`${usesLeft} - 1\` }).where(and(token, gt(usesLeft, 0)))` et vérifier le
   nombre de lignes affectées.
5. **Cookies Better Auth non explicites** : design §8 promet `Secure` + `SameSite=Lax` ; aucune config
   `advanced.cookieAttributes` dans `auth.ts`. À expliciter (et `trustedOrigins`/URL de prod au déploiement).
6. **Content-Type d'upload masquable** : `maps.ts` se fie à `file.type` (client-déclaré) ; pas de
   vérification des magic bytes png/jpg/webp. Faible risque contexte privé, ~15 min de fix.
7. **Routes dev exposées** : `POST /api/characters/seed/:campaignId` accessible à tout membre →
   pollution. Gater par var d'env ou supprimer avant prod.
8. **XSS (à anticiper phase 8)** : rendu actuel échappé par Svelte (OK). Le futur rendu markdown du
   `body` DRS/homebrew (MJ→journal joueurs) devra passer par DOMPurify, sinon injection stockée.
9. **Limits** : pas de quota messages WS/s ni taille max JSON (tâche 10.2 ouverte) ; le brouillard,
   lui, est bien borné (`FOG_MAX_REVEALS=600`, espacement — bon exemple à dupliquer ailleurs).
10. CSRF : POST + cookie SameSite=Lax + `Content-Type: application/json` = préflight requis →
    couvert, à condition de garder Lax (cf. #5).

  `marchandises/`, `montures-et-vehicules/`, `poisons/`, `pieges/`, `maladies/`, `folie/`,
  `objets-opposition/`, `objets-magiques-intelligents/`, + les chapitres de règles

  `gerer-la-sante-du-personnage/README.md` → la liste codée en dur (13 états) ne couvre pas la
  réalité DRS.
- Liens internes du DRS = **chemins absolus de wiki** (`[jet de sauvegarde](/utiliser-les-caracteristiques/#jets-de-sauvegarde)`)
  → la résolution `compendium://cat/slug` doit mapper ces chemins, pas du relatif.
- Format frontmatter monstre (vérifié sur aboleth) : `abilityScores` (map), `ac` (map imbriquée),
  `skills` (liste d'objets), `savingThrows` (liste), `movement`, `senses`, `telepathy`,
  `challenge`, `source`, `source_page` — compatible avec le parser prévu 8.1.

**Conclusion** : avant de coder le pipeline, faire une **table de mappage catégories canoniques
(les 10 du R11.2) → sources DRS + mode de parsing (fiche vs découpage de tableau)**, sinon les
pickers « arme / sort / don / capacité » de la feuille (R10.7) et les tooltips (R11.6) n'auront
pas de données.
